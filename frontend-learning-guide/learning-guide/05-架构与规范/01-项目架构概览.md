## 1. 技术栈总览

### 开发工具
- **pnpm** - 包管理器
- **Turborepo** - Monorepo 构建工具
- **Biome** - 代码格式化和 Lint

## 2. Monorepo 结构

### 为什么使用 Monorepo？

```
单仓库（Monorepo）优势：
✅ 代码共享容易（UI 组件、工具函数、类型定义）
✅ 统一的依赖管理和版本控制
✅ 原子化提交（跨包修改在一个 commit）
✅ 更容易重构（IDE 全局搜索和替换）
```

### 项目结构详解

```
frontend/
```

## 3. BFF 网关模式（重要！）

### 什么是 BFF？

**BFF = Backend For Frontend**（为前端服务的后端层）

```
客户端组件
    ↓ fetch('/api/users')
Next.js API Route (BFF 层)
    ↓ 转发 + 鉴权 + 数据转换
Python 后端 API
    ↓
数据库
```

### 为什么需要 BFF？

```typescript
// ❌ 禁止：客户端直接调用后端
'use client';
function UserList() {
  // 问题：
  // 1. 暴露后端 URL
  // 2. 无法在客户端安全存储 token
  // 3. CORS 问题
  // 4. 无法做请求拦截和转换
  const users = await fetch('https://backend-api.com/users');
}

// ✅ 正确：通过 BFF 转发
'use client';
function UserList() {
  // 优势：
  // 1. 隐藏后端 URL
  // 2. 服务端管理 token
  // 3. 统一错误处理
  // 4. 可以做数据转换和聚合
  const users = await fetch('/api/users');
}
```

### BFF 层实现示例

```typescript
// apps/web/src/app/api/users/route.ts
import { NextRequest, NextResponse } from 'next/server';

const BACKEND_URL = process.env.BACKEND_API_URL;

export async function GET(request: NextRequest) {
  try {
    // 1. 获取用户 token（从 cookie 或 header）
    const token = request.cookies.get('auth-token')?.value;
    
    // 2. 转发到后端 API
    const response = await fetch(`${BACKEND_URL}/api/v1/users`, {
      headers: {
        'Authorization': `Bearer ${token}`,
        'Content-Type': 'application/json',
      },
    });
    
    if (!response.ok) {
      throw new Error('Backend API error');
    }
    
    // 3. 获取数据
    const data = await response.json();
    
    // 4. 可选：数据转换
    const transformedData = data.items.map(user => ({
      ...user,
      fullName: `${user.firstName} ${user.lastName}`,
    }));
    
    // 5. 返回给前端
    return NextResponse.json({
      success: true,
      data: transformedData,
    });
  } catch (error) {
    return NextResponse.json(
      { success: false, error: 'Failed to fetch users' },
      { status: 500 }
    );
  }
}
```

### Server Components vs Client Components

```typescript
// ===== Server Component（默认）=====
// apps/web/src/app/[locale]/dashboard/page.tsx
import { getTranslations } from 'next-intl/server';
import { db } from '@/db';

// 可以直接访问数据库
export default async function DashboardPage() {
  const t = await getTranslations('Dashboard');
  
  // 直接查询数据库（服务端）
  const stats = await db.query.stats.findFirst();
  
  return (
    <div>
      <h1>{t('title')}</h1>
      <StatsDisplay stats={stats} />
    </div>
  );
}

// ===== Client Component =====
// apps/web/src/components/dashboard/interactive-chart.tsx
'use client';  // 必须声明

import { useState } from 'react';
import { useTranslations } from 'next-intl';

export function InteractiveChart() {
  const t = useTranslations('Dashboard');
  const [filter, setFilter] = useState('month');
  
  // 可以使用 Hooks 和交互
  return (
    <div>
      <select value={filter} onChange={(e) => setFilter(e.target.value)}>
        <option value="week">{t('week')}</option>
        <option value="month">{t('month')}</option>
      </select>
      {/* 图表内容 */}
    </div>
  );
}
```

### 何时使用 Server Components vs Client Components？

| 场景 | 推荐 |
|------|------|
| 纯展示，无交互 | Server Component |
| 需要 useState、useEffect | Client Component |
| 直接访问数据库 | Server Component |
| 需要事件处理（onClick 等） | Client Component |
| SEO 重要的内容 | Server Component |
| 需要浏览器 API（localStorage） | Client Component |

**原则**：默认使用 Server Component，需要交互时才使用 Client Component。

## 5. 数据流

### 读取数据（Server Component）

```typescript
// 服务端直接读取
export default async function UsersPage() {
  // 直接查询数据库
  const users = await db.query.users.findMany();
  
  return <UserList users={users} />;
}
```

### 写入数据（Server Actions）

```typescript
// actions/users.ts
'use server';

import { db } from '@/db';
import { revalidatePath } from 'next/cache';

export async function createUser(formData: FormData) {
  const name = formData.get('name') as string;
  const email = formData.get('email') as string;
  
  // 写入数据库
  await db.insert(users).values({ name, email });
  
  // 刷新页面缓存
  revalidatePath('/users');
  
  return { success: true };
}

// 组件中使用
'use client';
export function CreateUserForm() {
  return (
    <form action={createUser}>
      <input name="name" />
      <input name="email" />
      <button type="submit">Create</button>
    </form>
  );
}
```

### 客户端状态（Zustand）

```typescript
// stores/user-store.ts
import { create } from 'zustand';

interface UserState {
  currentUser: User | null;
  setCurrentUser: (user: User) => void;
}

export const useUserStore = create<UserState>((set) => ({
  currentUser: null,
  setCurrentUser: (user) => set({ currentUser: user }),
}));

// 组件中使用
'use client';
export function UserProfile() {
  const currentUser = useUserStore((state) => state.currentUser);
  
  return <div>{currentUser?.name}</div>;
}
```

## 7. 组件复用层级

```
优先级（从高到低）：

1. @creativault/ui（v2）
   ↓ 基础 UI 组件（Button, Dialog, Input 等）
   
2. apps/web/src/components/ui/
   ↓ 业务 UI 组件（基于 @creativault/ui 组合）
   
3. apps/web/src/components/{module}/
   ↓ 模块特定组件（Growth、Agent、Favorites 等）
   
4. 页面级组件（page.tsx 内部）
   ↓ 仅当前页面使用的组件
```

### 示例

```typescript
// ===== 1. 使用 @creativault/ui =====
import { Button } from '@creativault/ui/button';
import { Dialog, DialogContent } from '@creativault/ui/dialog';

// ===== 2. 业务 UI 组件 =====
// apps/web/src/components/ui/data-table.tsx
import { Table } from '@creativault/ui/table';

export function DataTable({ data }) {
  // 基于 @creativault/ui 的 Table，添加业务逻辑
  return <Table>...</Table>;
}

// ===== 3. 模块特定组件 =====
// apps/web/src/components/growth/creator-card.tsx
import { Card } from '@creativault/ui/card';
import { Button } from '@creativault/ui/button';

  // Growth 模块专用的达人卡片

// ===== 4. 页面级组件 =====

  // 仅在此页面使用的小组件，直接写在这里

  return (
    <div>
      <QuickActionButton />
      <CreatorCard creator={...} />
    </div>
  );
}
```

## 8. 开发工作流

### 1. 启动开发服务器

```bash
cd frontend
pnpm dev              # 启动 web 应用（默认 http://localhost:3000）
pnpm dev:admin        # 启动 admin 应用
pnpm dev:dubhe        # 启动 dubhe 应用
```

### 2. 代码检查

```bash
pnpm lint             # Biome 代码检查
pnpm typecheck        # TypeScript 类型检查
pnpm test             # 运行测试
```

### 3. 开发新功能流程

```
1. 查找可复用组件
   → 检查 @creativault/ui
   → 检查 apps/web/src/components/

2. 创建页面或组件
   → 确定是 Server Component 还是 Client Component
   → 添加类型定义
   → 实现逻辑

3. 添加国际化
   → 在 messages/en.json 和 zh.json 中添加翻译 key

4. 数据获取
   → Server Component：直接查询或调用 API
   → Client Component：通过 API Route（BFF）

5. 测试
   → 浏览器手动测试
   → 检查类型错误（pnpm typecheck）
   → 检查 Lint（pnpm lint）
```

## 9. 与后端的交互

### 数据流向

```
前端组件
  ↓ 1. 调用 /api/* (BFF)
Next.js API Route
  ↓ 2. 转发到后端，添加 /api/v1 前缀
Python FastAPI 后端
  ↓ 3. 查询数据库
PostgreSQL / Hologres
  ↓ 4. 返回数据
Python 后端
  ↓ 5. 返回 JSON
Next.js API Route
  ↓ 6. 可选：数据转换
前端组件
  ↓ 7. 渲染 UI
```

### 类型同步


## 10. 关键概念对比

### 前端 vs 后端思维

| 概念 | 后端（FastAPI） | 前端（Next.js + React） |
|------|----------------|----------------------|
| 入口 | `server.py` | `app/layout.tsx` + `app/page.tsx` |
| 路由 | `@router.get("/users")` | `app/users/page.tsx` |
| 数据获取 | `db.query()` | Server Component 直接查询 或 API Route |
| 数据写入 | `db.insert()` | Server Actions |
| 状态 | 无状态（RESTful） | 有状态（React State、Zustand） |
| 模板 | Jinja2（很少用） | JSX（React 组件） |
| 依赖注入 | `Depends(get_db)` | React Context / Props |
| 错误处理 | `try/except` + HTTP 状态码 | Error Boundaries + UI 反馈 |

## 常见问题

### Q: Monorepo 中如何添加依赖？
A:
```bash
# 给特定包添加依赖
cd apps/web
pnpm add lodash

# 给所有包添加依赖（根目录）
pnpm add -w typescript

# 添加 workspace 包依赖
pnpm add @creativault/ui --workspace
```

### Q: 如何调试 Server Component？
A: 使用 `console.log`，输出会在终端（服务端），而非浏览器控制台。

### Q: 什么时候用 API Route，什么时候用 Server Actions？
A:
- **Server Actions**：表单提交、数据变更（推荐）
- **API Route**：需要被外部调用、需要特定 HTTP 方法、需要自定义响应头

### Q: 为什么有些组件在 packages/ui，有些在 apps/web/src/components？
A:
- `packages/ui`：通用 UI 组件，可被多个 app 复用
- `apps/web/src/components`：web 应用专用组件
