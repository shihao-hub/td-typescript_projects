# taskmon 版本与 CPU 可控开关使用指南

针对用户反馈的 **“新版本 CPU 信息占用过多宽度、更偏好原版清爽内存视图”** 的需求，当前版本已完成**可控参数升级**：

> **无需在两个不同的 exe 之间频繁替换！**
> 
> 现在单一可执行程序（`taskmon.exe`）已将两者完美统一：
> 1. **默认启动（`taskmon`）**：完全恢复原版样貌（**纯内存清爽视图**，不显示 CPU 占用列与 CPU 摘要，给进程名和分布条留下最大宽度）；
> 2. **按需查看（`taskmon --cpu`）**：加 `--cpu` 参数或在交互界面中**按 `c` 键**，随时动态开启/隐藏 CPU 占用列与系统 CPU 摘要。

---

## 1. 默认视图 vs CPU 视图对比

| 特性 / 维度 | 默认视图（纯内存清爽版，默认） | CPU 视图（`--cpu` 参数 或 按 `c` 键） |
| :--- | :--- | :--- |
| **顶部状态栏** | `进程 · 分组 · 物理内存 XX% 已用 · 工作集合计 · 刷新 2s` | 追加 **`CPU XX.X%`** 动态使用率与分级染色警示 |
| **分组视图（Group）** | 列：`#`、`进程 / 组`、`PID`、`内存`、`占比`、`分布` | 插入 **`CPU`** 列（组总 CPU% 与成员单进程 CPU%） |
| **进程树视图（Tree）** | 列：`#`、`进程树`、`PID`、`自身`、`子树`、`占比`、`分布` | 插入 **`CPU`**（自身）与 **`子树CPU`**（整棵子树合计）两列 |
| **排序机制（`s`）** | 默认按内存降序；按 `s` 切至 CPU 排序时**自动呼出 CPU 列** | 支持快捷键 **`s`** 或参数 `-s cpu` / `-s mem` 动态切换排序 |
| **快捷键 `c`** | **随时按 `c` 切换显示 / 隐藏 CPU 列** | 同左 |
| **适用场景** | 终端宽度有限、仅排查内存泄漏或占用、喜欢清爽无干扰（推荐日常使用） | 需要综合监控机器 CPU 飙高、寻找算力失控的父子进程链 |

## 2. 常用操作命令

### 日常运行

```powershell
# 1. 默认清爽纯内存视图（最干净、空间最大）
.\taskmon.exe

# 2. 默认进程树视图（纯内存）
.\taskmon.exe --tree

# 3. 开启 CPU 监控运行
.\taskmon.exe --cpu
.\taskmon.exe --tree --cpu

# 4. 排序方式
.\taskmon.exe -s cpu    # 启动即按 CPU 排序（自动开启 CPU 列）
```

### 交互界面快捷键

- **`c`**：一键切换 CPU 列的显示与隐藏（随时按，无需重启）。
- **`s`**：在按内存排序与按 CPU 排序之间切换（切换到 CPU 时会自动显示 CPU 列）。
- **`T`**：在分组视图与进程树视图之间切换。

## 3. 重新构建与打包（开发与发版）

如果修改了代码或想重新编译生成最新的单文件 exe：

```powershell
# 1. 编译 TypeScript
pnpm build

# 2. 运行单元测试验证
pnpm test

# 3. 打包生成 release/ 目录下的单文件 exe（依赖 Bun）
pnpm exe
# 或使用 Git tag 模式（自动标注提交号与脏树状态）：
# bun scripts/build-exe.ts --tag

# 4. 将 release/ 下最新构建的 exe 覆盖至项目根目录 taskmon.exe
pnpm use
```

## 4. 历史版本存档（若确实需要独立回退旧版 exe）

在 `release/` 目录中仍保留有未包含 CPU 功能的历史版本构建产物：

- **历史纯内存版**：`release/taskmon-v0.2.1+0003.g580aadc.exe`
- **历史旧版**：`release/taskmon-v0.2.1.exe`

如需强行回退至历史提交编译：
```powershell
# 检出加入 CPU 之前的 Git 提交 84705e5
git checkout 84705e5 -- .
pnpm exe
git checkout HEAD -- .
```

但在最新版本支持 `--cpu` 和 `c` 开关后，**同一可执行程序已可完美兼顾清爽内存与 CPU 监测两项需求**。
